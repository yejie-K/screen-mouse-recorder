# 已知限制

## 分析链路

1. 自动功能事件识别对固定区域依赖较强。没有合适的功能事件区域时，OCR可能只产出指标候选。
2. OCR候选必须人工复核；不能把自动结果直接当作确认事件或确认指标。
3. 不同游戏的固定UI位置和词汇不同，区域profile不能跨游戏静默复用。
4. 玩法/系统开放节奏图当前是候选或确认数据驱动的确定性 Pillow 图，不是大模型自由绘图。

## 发布与环境

1. 当前快照没有便携 EXE，Windows 目标机需要 Python 3.10+ 和 FFmpeg。
2. RapidOCR是可选依赖；未安装时录屏核心仍可运行，但 OCR 工作流不能执行。
3. GitHub仓库不包含真实录屏、Session、模型文件、OCR结果或本机日志。

## 数据状态

真实测试数据的复核状态以各工作空间的 `journey_workspace.json` 为准，不以历史对话或旧 PNG 判断。
