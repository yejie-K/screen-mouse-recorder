# 玩法/系统开放节奏图契约

## 目的

将人工确认后的首次开放事件绘制成可复现的时间轴图。图表由本地 Pillow 脚本确定性生成；大模型只补充结构化语义候选，不直接生成图片，也不能改写已确认的事件名称和时间。

## 时间规则

- 以累计有效游玩时间计算游玩日，不使用自然日期。
- 每累计 60 分钟为 1 个游玩日。
- `play_day_index = floor(global_time_ms / 3600000) + 1`。
- `day_time_ms = global_time_ms % 3600000`。
- 完整游玩日显示 0～60 分钟；最后不足 60 分钟的一天按实际时长显示。
- 单次总时长不超过 60 分钟时仍使用同一条时间轴，并执行与多日图一致的事件矩阵和连线规则；不得回退到事件块分布在时间轴上下两侧的旧布局。

## 输入约束

会话必须提供：

- `total_play_time_ms`：累计有效游玩时长。
- `virtual_day_minutes`：固定为 `60`。
- `virtual_day_count`：总游玩日数。

事件必须提供：

- `global_time_ms`：跨录屏累计时间。
- `play_day_index`：事件所属游玩日，从 1 开始。
- `day_time_ms`：事件在当天的相对时间。
- `event_type`、`event_name` 和人工确认的证据引用。

当前图只读取 `new_feature_unlocked`。重复出现、预告但未开放、无证据事件不得进入正式图。

## 布局规则

- 所有游玩日共用一条连续时间轴，每 60 分钟使用“第 N 天”区段标识。
- 时间轴上方只显示循环/阶段总结条带。优先读取结构化 `cycle_summaries`；缺失时使用本地阶段候选。
- 所有具体事件块统一显示在时间轴下方；每个游玩日内部按时间顺序放入固定列宽矩阵，先从上到下填满一列，再进入右侧下一列。
- 矩阵首行的每个块是对应列的锚点，使用两段斜折线连接时间轴上的真实时间点。
- 第二行及以下不再单独连接时间轴，只与同列上一块垂直串联；完整事件时间仍保留在结构化报告中。
- 事件越密，矩阵行数和画布高度越大。
- 天数增加时画布可以动态增宽，但不得分页或增加第二条时间轴。
- 事件块连接到累计时间轴上的准确位置。
- 每个块显示事件名和开放条件；没有可靠开放等级时显示当天分钟数。
- 填充色与外框色表达两个独立维度，不得混用。
- 填充色读取 `gameplay_form` 并归并为成长养成、BOSS、副本、日常任务、竞技排行、社交协作、活动、商业化、通用功能或其他。
- 外框色读取 `interaction_mode`：PVE 蓝、PVP 红、GVG 紫；社交、养成、功能和未知使用各自辅助框色。
- 多标签事件按固定优先级选择一种主填充和主外框，原始完整标签仍保留在结构化数据中。

## 输出约束

图表报告必须保留：

- `layout_mode`：`single_session` 或 `continuous_multi_day`。
- `day_count`、`page_count`；当前连续时间轴固定 `page_count = 1`。
- `day_summaries`：每天时长、事件数和使用的轨道数。
- `nodes`：图上节点及其分类候选、开放条件和复核状态。
- `cycle_summary_candidates`：时间轴上方展示的循环总结候选。
- `outputs`：全部 PNG 文件名。

`manifest.json` 保留兼容字段 `outputs.open_timeline`，同时使用 `outputs.open_timeline_pages` 列出图表文件；连续时间轴当前只包含一个文件。

每次生成还必须提供以下交接文件。当前工作空间生成器使用与PNG同前缀的中文文件名；旧草稿包中的 `chart_gameplay_open_timeline_*` 名称只作历史兼容：

- `玩法系统开放节奏.agent_spec.json`：机器可读的完整绘图输入、分类映射、视觉编码、布局规则和可编辑边界。
- `玩法系统开放节奏.agent_report.md`：供其他 agent 或人工快速阅读的游戏分类拆解与复现说明。
- `玩法系统开放节奏.input.json`：该图使用的结构化语义输入副本。
- `玩法系统开放节奏.taxonomy.json`：该图使用的分类规则副本。
- `玩法系统开放节奏.contract.md`：本契约在产物目录内的固定副本。

## 复核边界

- 分类、开放条件和阶段语义仍需人工复核。
- 时间戳以结构化事件时间为准，OCR 只能作为校验或候补证据。
- 调整本契约字段、分页命名或分类枚举时，必须同步检查输入 schema、AI 提示词、图表报告及对外接口文档。
